# VC Profile Validator Report Format

This document defines the structure and behavior of validation reports produced by the current implementation.

## Related Artifacts

| Artifact | Description |
| --- | --- |
| [report-schema.json](report-schema.json) | JSON schema for the structured report format |
| [sample-report.json](sample-report.json) | Sample JSON report generated by the current implementation |
| [sample-report.html](sample-report.html) | Sample HTML rendering generated by the current implementation |

## Report Structure

A validation report contains four top-level sections:

| Section | Description |
| --- | --- |
| `profile` | Identifies the profile used for validation |
| `summary` | Contains error, warning, info, and overall result counts |
| `findings` | Contains failed rule results only |
| `metadata` | Contains target, timestamp, validator metadata, and optional input metadata |

## Profile Section

| Field | Description |
| --- | --- |
| `id` | Stable profile identifier |
| `name` | Human-readable profile name |
| `version` | Profile version used during validation |

## Summary Section

| Field | Description |
| --- | --- |
| `errors` | Count of findings with severity `error` |
| `warnings` | Count of findings with severity `warning` |
| `infos` | Count of findings with severity `info` |
| `result` | `fail` if `errors > 0`; otherwise `pass` |
| `rulesTotal` | Total number of rules evaluated |
| `findingsTotal` | Total number of findings included in the report |

## Findings Section

Each finding corresponds to a failed rule evaluation.

| Field | Description |
| --- | --- |
| `ruleId` | Rule identifier from the profile |
| `severity` | `error`, `warning`, or `info` |
| `target` | `vc` or `vp` |
| `path` | Rule path, when present |
| `message` | Failure message derived from rule `message` or `description` |
| `remediation` | Remediation guidance, when present |
| `evidence` | Resolved values, when present |

## Metadata Section

| Field | Description |
| --- | --- |
| `target` | Validation target: `vc` or `vp` |
| `timestamp` | UTC timestamp when the report was generated |
| `validator.name` | Validator name |
| `validator.version` | Validator version |
| `input.source` | Optional input source description |
| `input.sha256` | Optional SHA-256 hash of the input |

## Output Behavior

- JSON reports are generated for all validation runs
- HTML reports are generated alongside JSON when reports are written to disk
- Findings preserve profile rule order
- Reports include only failed findings, not successful rule evaluations

## Result Semantics

| Condition | Result |
| --- | --- |
| No `error` findings are present | `summary.result` is `pass` |
| One or more `error` findings are present | `summary.result` is `fail` |
| `warning` and `info` findings are present without any `error` findings | Included in counts but do not change `summary.result` to `fail` |
